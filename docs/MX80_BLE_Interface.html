途一智能体脂秤 MX80 BLE 接口文档

设备名：yoda.scales.mx80　协议：BLE GATT + Xiaomi MiBLE 安全会话　文档版本：1.0
本文只记录已确认行为：扫描识别、GATT连接、TOKEN登录、加密测量流、ACK、体重及稳定状态解析。

1. 能力与边界

项目状态说明
实时/稳定体重已确认单位 kg，分辨率 0.01 kg。
稳定状态已确认测量载荷状态字节 bit 0。
体脂、水分、肌肉、骨量等未发现传输字段已解密的数据流中没有确认的独立字段，本文不定义。
11 94 字段未知空载、79.78 kg、94.41 kg、95.03 kg样本中均出现，不能定义为阻抗。
重新注册/重置绑定不纳入本文本文仅描述已持有有效12字节TOKEN时的登录。
体重以外的身体成分若由接入方计算，必须标注为估算值，不能声称由MX80直接测得或传输。

2. 前置条件

  • BLE中央设备支持GATT通知、Write Without Response、MTU请求和AES-CCM。
  • 持有该设备对应的有效米家云TOKEN：固定12字节，即24个十六进制字符。
  • TOKEN不是常见的BLE Key；错误或失效TOKEN会导致登录失败。
  • 同一时刻不要让米家与第三方App同时连接秤。
TOKEN的云端获取接口未在本项目中得到可公开复现的确认，因此不在本文中描述。

3. 扫描与识别

使用无过滤BLE扫描即可发现设备。已确认的识别信息：

本地名称yoda.scales.mx80
Service Data UUID0000FE95-0000-1000-8000-00805F9B34FB
一次实测Service Data10 59 D1 39 00 51 F4 00 00 00 80

广播中的FE95数据在多次扫描中保持不变，未确认其中包含体重。体重应通过下述GATT安全通道读取。

4. GATT服务与特征

以下特征均位于服务 0000FE95-0000-1000-8000-00805F9B34FB。

短UUID完整UUID已确认用途
000400000004-0000-1000-8000-00805F9B34FB可读设备信息；样本值为ASCII 2.1.0_0131。
001000000010-0000-1000-8000-00805F9B34FB认证控制写入及登录结果通知。
001900000019-0000-1000-8000-00805F9B34FB认证数据双向传输。
001A0000001A-0000-1000-8000-00805F9B34FB需订阅；当前样本未确认其业务载荷。
001B0000001B-0000-1000-8000-00805F9B34FB加密测量通知及应用层ACK。
001C0000001C-0000-1000-8000-00805F9B34FB连接预初始化。

通知通过标准CCCD 00002902-0000-1000-8000-00805F9B34FB启用。客户端必须同时执行本地通知注册和CCCD写入。

5. 已验证连接顺序

  1. 建立LE GATT连接并发现服务；此时先使用默认MTU。
  2. 按顺序订阅 001B、001A、001C。
  3. 向 001C 写入 00 00，执行预初始化。
  4. 预初始化完成后订阅 0019，读取 0004。
  5. 请求MTU 247。若请求失败，现有MTU仍可继续，但分片行为可能不同。
  6. 执行A4/F2初始化，随后订阅 0010。
  7. 使用12字节TOKEN登录。
  8. 收到 21 00 00 00 后开始解密 001B 测量通知。

认证写入使用 Write Without Response。已验证实现将相邻写入间隔设为约10 ms。

6. 001C预初始化

设备通知客户端动作
00 02 03 08向001C写 08 01 00。
08 LL OO ...令 payloadLength = LL - 1。若小于17，写 03；否则写 08 01 (OO + payloadLength)。
首字节为 03预初始化完成，进入订阅0019、读0004及请求MTU阶段。

LL、OO均按无符号8位整数处理。

7. A4/F2初始化

  1. 向 0010 写 A4。
  2. 设备在 0019 上发送以 00 00 04 开头的帧。
  3. 复制整帧，将第3字节由 04 改为 05，原样写回 0019。
  4. 当该帧第4字节为 01 时，此阶段完成；随后重新启用 0010 通知。

8. TOKEN登录

8.1 常量

接收方已准备00 00 01 01
设备已收到00 00 01 00
客户端确认收到00 00 03 00
发送客户端随机数命令00 00 00 0B 01 00
设备随机数命令00 00 00 0D 01 00
设备认证信息命令00 00 00 0C 02 00
发送客户端认证信息命令00 00 00 0A 01 00

8.2 流程

  1. 生成16字节密码学安全随机数 appRandom。
  2. 向0010写 24 00 00 00；向0019写“发送客户端随机数命令”。
  3. 设备发送“接收方已准备”后，向0019写 01 00 || appRandom。
  4. 设备发出“设备随机数命令”时，回复“接收方已准备”。收到16字节 deviceRandom 后，回复“客户端确认收到”。
  5. 设备发出“设备认证信息命令”时，回复“接收方已准备”。收到32字节 remoteInfo 后，回复“客户端确认收到”，再发送“发送客户端认证信息命令”。
  6. 按8.3计算并校验密钥。设备再次发送“接收方已准备”后，写 01 00 || loginResponse。
  7. 设备在0010通知 21 00 00 00 表示登录成功；23 00 00 00 表示登录被拒绝。

8.3 密钥计算

salt = appRandom || deviceRandom
derived = HKDF-SHA256(
    IKM  = token,                 // 12 bytes
    salt = salt,                  // 32 bytes
    info = UTF8("mible-login-info"),
    L    = 64
)

deviceKey = derived[0..15]
appKey    = derived[16..31]
deviceIv  = derived[32..35]

expectedRemoteInfo = HMAC-SHA256(deviceKey, deviceRandom || appRandom)
loginResponse      = HMAC-SHA256(appKey, appRandom || deviceRandom)

只有 remoteInfo == expectedRemoteInfo 时才能继续。

8.4 认证通知封装

MTU 247样本中，设备可直接发送：

00 00 02 TT PAYLOAD...

客户端处理时跳过前4字节，将 PAYLOAD 交给登录状态机。客户端发送不超过240字节的数据时使用 01 00 || DATA。

9. 001B测量包解密与ACK

9.1 加密包

offset  size  confirmed meaning
0       4    header (observed: 00 00 02 00)
4       2    packet counter bytes; also used in nonce
6       N    AES-CCM ciphertext followed by 4-byte authentication tag

每收到一个有效候选测量包，客户端必须立即向 001B 写 00 00 03 00。设备逐包等待该ACK；不发送ACK时，后续测量通知会停止。

9.2 AES-CCM参数

key   = deviceKey                     // 16 bytes
nonce = deviceIv || 00 00 00 00 || packet[4] || packet[5] || 00 00
tag   = 4 bytes (32 bits)
AAD   = none
input = packet[6..end]                // ciphertext + tag

算法为 AES/CCM/NoPadding。

10. 解密明文与体重解析

10.1 外层明文

已确认的测量明文长度至少27字节，前缀为 1B 20。字节11至26为16个ASCII十六进制字符，解码后得到8字节测量载荷。

1B 20 .. .. 04 01 03 01 00 10 A0 39 36 41 45 31 46 32 41 31 31 39 34 32 35 35 37
                                      |----------- ASCII "96AE1F2A11942557" -----------|

10.2 8字节测量载荷

偏移长度含义解析
02未知不解释、不参与体重计算。
22体重无符号大端整数，单位0.01 kg。
42未知不解释。
61状态bit 0为1表示稳定；为0表示未稳定。
71校验和前7字节无符号求和后取低8位。
checksum = (b0 + b1 + b2 + b3 + b4 + b5 + b6) & 0xFF
weightRaw = (b2 << 8) | b3
weightKg = weightRaw / 100.0
stable = (b6 & 0x01) != 0

10.3 已验证样本

载荷结果

96 A3 24 E1 11 94 25 0894.41 kg，稳定，校验和正确。

11. 最小实现伪代码

scan for name == "yoda.scales.mx80" or service UUID FE95
connect GATT
discover services
subscribe 001B, 001A, 001C
run 001C preflight
subscribe 0019
read 0004
request MTU 247
run A4/F2 preamble
subscribe 0010
login with 12-byte token

on 001B notification(packet):
    writeWithoutResponse(001B, 00 00 03 00)
    plain = AES_CCM_decrypt(packet, deviceKey, deviceIv)
    if plain startsWith 1B 20 and plain.length >= 27:
        payload = hexDecode(ASCII(plain[11..26]))
        if checksum(payload[0..6]) == payload[7]:
            publish weight and stable flag

12. 错误处理

  • GATT连接失败或断开：关闭当前GATT对象，等待秤重新唤醒后重连。
  • 登录结果 23 00 00 00：TOKEN已被设备拒绝，不继续解密。
  • AES-CCM认证失败：丢弃该包，不输出体重。
  • ASCII十六进制非法、长度不足或校验和错误：丢弃该包。
  • 体重为0：视为空载状态，不作为有效称重记录。
  • 保存最终测量时建议只保存 stable=true 且体重大于0的记录。
